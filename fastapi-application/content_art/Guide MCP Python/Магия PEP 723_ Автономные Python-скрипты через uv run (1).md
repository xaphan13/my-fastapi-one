Использование встроенных метаданных согласно стандарту **PEP 723 (Inline Script Metadata)** позволяет создавать полностью самодостаточные Python-скрипты. Вы можете объявить все необходимые сторонние библиотеки (такие как requests и beautifulsoup4) прямо внутри комментариев в заголовке файла, а **uv run** автоматически развернет изолированное окружение, скачает нужные версии пакетов и запустит ваш код.

### Как устроен блок метаданных PEP 723

Этот блок представляет собой фрагмент конфигурации в формате **TOML**, записанный в виде комментариев в самом начале вашего Python-файла. Он должен начинаться со строки \# /// script и заканчиваться строкой \# ///.  
Вот пример готового скрипта **parser.py**, который использует requests и beautifulsoup4 для парсинга веб\-страницы:  
\#\!/usr/bin/env \-S uv run \--script  
\# /// script  
\# requires-python \= "\>=3.10"  
\# dependencies \= \[  
\#     "requests",  
\#     "beautifulsoup4",  
\# \]  
\# ///

import requests  
from bs4 import BeautifulSoup

def main():  
    url \= "https://example.com"  
    print(f"Отправка запроса к {url}...")  
      
    \# Выполняем запрос с помощью requests  
    response \= requests.get(url)  
      
    \# Парсим HTML с помощью BeautifulSoup  
    soup \= BeautifulSoup(response.text, "html.parser")  
    title \= soup.find("h1")  
      
    print("\\nРезультат парсинга:")  
    print(f"Заголовок страницы: {title.text.strip() if title else 'Не найден'}")

if \_\_name\_\_ \== "\_\_main\_\_":  
    main()

### Как это запускать и использовать

#### 1\. Прямой запуск через uv run

Вам не нужно вручную создавать виртуальное окружение (venv), устанавливать пакеты через pip или создавать файл requirements.txt. Достаточно выполнить команду:  
uv run parser.py  
**Что произойдет под капотом:**

1. uv прочитает заголовок файла и найдет блок \# /// script.  
2. Он создаст ephemeral (временное/эфемерое) виртуальное окружение специально для этого запуска.  
3. Скачает и установит в него requests и beautifulsoup4.  
4. Запустит скрипт внутри этого окружения.  
5. При повторных запусках uv мгновенно использует кэшированное окружение, не скачивая библиотеки заново, если состав зависимостей не изменился.

#### 2\. Запуск как исполняемого файла (Shebang)

Если вы добавите в самую первую строку скрипта специальный шебанг:  
\#\!/usr/bin/env \-S uv run \--script  
И сделаете файл исполняемым в терминале:  
chmod \+x parser.py  
Вы сможете запускать его напрямую, как обычную системную утилиту, и он сам вызовет uv run для подготовки окружения:  
./parser.py

### Полезные команды uv для работы со скриптами

* **Автоматическое добавление зависимости в скрипт:**Вместо того чтобы вручную редактировать TOML-блок, вы можете попросить uv самостоятельно прописать библиотеку в метаданные файла:  
* uv add \--script parser.py "requests\<3" "beautifulsoup4"  
* Команда сама создаст или обновит блок \# /// script внутри вашего файла.  
* **Фиксация версий (Locking):**Для обеспечения максимальной воспроизводимости в продакшене вы можете зафиксировать точные версии зависимостей вашего скрипта (аналог uv.lock для проектов):  
* uv lock \--script parser.py  
* Это создаст файл parser.py.lock рядом с вашим скриптом.  
* **Поиск виртуального окружения скрипта:**Если вашей IDE (например, VS Code с расширением Pylance) нужно подсказать, откуда брать автодополнение для установленных библиотек, вы можете узнать путь к окружению этого скрипта с помощью команды:  
* uv python find \--script parser.py

*Эта технология идеально подходит для написания кастомных MCP-серверов на Python (особенно с использованием FastMCP), так как позволяет распространять весь сервер в виде одного-единственного файла, который гарантированно запустится на любой машине с установленным uv.*
