Подключение MCP-серверов к конкретному субагенту в Qwen Code осуществляется **декларативно через файл конфигурации (манифест) субагента** 1, 2\. В отличие от глобального подключения, изоляция MCP-серверов на уровне субагента позволяет запускать их только на время его жизненного цикла 3\. Это предотвращает «засорение» контекстного окна главной сессии лишними схемами инструментов и экономит токены 3\.  
Для настройки выполните следующие шаги:

### Шаг 1\. Создайте или откройте файл субагента

Субагенты хранятся в виде Markdown-файлов с YAML-разметкой (frontmatter) в начале файла 4\. Найдите или создайте файл вашего субагента в одной из директорий 5:

* **На уровне проекта**: .qwen/agents/имя\_субагента.md 5  
* **На глобальном уровне**: \~/.qwen/agents/имя\_субагента.md 5

### Шаг 2\. Добавьте блок mcpServers во фронтматер (YAML)

В блоке метаданных субагента добавьте свойство **mcpServers** в виде объекта с настройками нужного сервера 4, 6\. Формат описания параметров совпадает с настройками в глобальном settings.json 6\.  
**Пример манифеста субагента (db-expert.md)**:  
```yaml
name: db-expert  
description: "Субагент для анализа и оптимизации баз данных"  
model: inherit  
approvalMode: auto-edit  
mcpServers:  
  sqlite-inspector:  
    command: "npx"  
    args:  
      \- "-y"  
      \- "@modelcontextprotocol/server-sqlite"  
      \- "--db-path"  
      \- "/absolute/path/to/production.db"  
```

Ты — эксперт по базам данных. Используй инструменты подключенного MCP-сервера sqlite-inspector для анализа схем таблиц и оптимизации медленных SQL-запросов.

### Как это работает под капотом:

1. **Жизненный цикл и экономия контекста**: Сервер MCP запускается исключительно в момент старта субагента и автоматически завершает свою работу (уничтожается) вместе с закрытием сессии субагента 3\. Главный агент не видит эти инструменты в основное время работы 3\.  
2. **Слияние и переопределение (Merge & Override)**: При вызове субагента его локальные mcpServers объединяются со списком MCP-серверов главной сессии 6\. В случае совпадения имен (коллизии ключей) конфигурация субагента имеет приоритет и заменяет глобальную спецификацию 6\.

### Шаг 3\. Тонкое управление инструментами MCP (Фильтрация прав)

Вы можете гибко настроить, какие именно инструменты созданного MCP-сервера будут доступны вашему субагенту 7:

* **По умолчанию**: Если у субагента не задан белый список инструментов (tools), он автоматически получает доступ ко всем инструментам подключенного к нему MCP-сервера 7\.  
* **Белый список (tools)**: Если вы используете белый список tools, субагент получит доступ только к тем MCP-инструментам, которые вы укажете в нем по именам 7, 8\.  
* **Черный список (disallowedTools)**: Вы можете точечно заблокировать нежелательные вызовы с помощью шаблонов 8:  
* mcp\_\_имя\_сервера\_\_имя\_инструмента — заблокирует конкретный инструмент конкретного MCP-сервера 8\.  
* mcp\_\_имя\_сервера — заблокирует абсолютно все инструменты этого MCP-сервера 8\.

*Пример с фильтрацией инструментов*:  
```yaml 
name: restricted-helper  
description: "Помощник с ограниченным доступом к инструментам"  
mcpServers:  
  puppeteer:  
    command: "npx"  
    args: \["-y", "@modelcontextprotocol/server-puppeteer"\]  
disallowedTools:  
  \- "mcp\_\_puppeteer\_\_screenshot" \# субагент сможет использовать puppeteer, но не сможет делать скриншоты  
```
После сохранения манифеста субагент мгновенно обновит свои параметры в реестре Qwen Code и будет готов к использованию 9, 10\.
