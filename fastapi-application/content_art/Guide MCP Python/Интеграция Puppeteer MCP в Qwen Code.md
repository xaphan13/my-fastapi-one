Для примера настроим один из самых популярных серверов — **Puppeteer MCP Server** (@modelcontextprotocol/server-puppeteer), который позволяет ИИ запускать браузер в фоновом режиме, переходить по веб\-страницам, кликать по элементам, вводить текст и парсить контент 1, 2\.  
Ниже приведены два способа его интеграции: **глобальный** (для всей системы Qwen Code) и **локальный** (изолированно для конкретного специализированного субагента-исследователя) 3, 4\.

### Способ 1\. Глобальное подключение в settings.json

Чтобы инструменты браузера были доступны во всех ваших сессиях Qwen Code, добавьте секцию mcpServers в ваш глобальный файл настроек \~/.qwen/settings.json 5, 6:  
{  
  "mcpServers": {  
    "web-browser": {  
      "command": "npx",  
      "args": \[  
        "-y",  
        "@modelcontextprotocol/server-puppeteer"  
      \],  
      "description": "Сервер Puppeteer для веб\-браузинга и автоматизации действий на веб\-страницах",  
      "timeout": 30000  
    }  
  }  
}

* **web-browser** — это произвольный алиас (имя) сервера в системе, который вы придумываете сами 6\.  
* **includeTools / excludeTools** (опционально) — вы можете прямо здесь ограничить список инструментов, импортируемых из этого MCP-сервера 7\. Например, добавив "excludeTools": \["puppeteer\_screenshot"\], вы заблокируете возможность делать скриншоты на уровне настроек этого сервера 7\.

### Способ 2\. Локальное подключение для конкретного субагента (web-scout.md)

Если вы не хотите засорять контекстное окно главного агента лишними веб\-инструментами, вы можете настроить запуск MCP-сервера только в момент работы специализированного субагента 8, 9\.  
Создайте файл .qwen/agents/web-scout.md в папке вашего проекта 10 со следующим содержимым 8:  
\---  
name: web-scout  
description: "Субагент для веб\-исследований, чтения онлайн-документации сайтов и парсинга страниц. use PROACTIVELY."  
model: inherit  
approvalMode: auto-edit  
mcpServers:  
  web-browsing:  
    command: "npx"  
    args:  
      \- "-y"  
      \- "@modelcontextprotocol/server-puppeteer"  
disallowedTools:  
  \- "mcp\_\_web-browsing\_\_puppeteer\_screenshot"  
\---

Ты — эксперт по анализу веб\-ресурсов. Твоя задача — исследовать сайты, читать документацию библиотек и собирать нужные данные для проекта.  
Используй инструменты подключенного MCP-сервера \`web-browsing\` для навигации. Тебе запрещено делать скриншоты, сфокусируйся на чтении текста страниц.

### 💡 Важные особенности работы с инструментами MCP:

* **Предотвращение конфликтов (Префиксы)**:Если разные MCP-серверы предоставляют инструменты с одинаковыми именами, Qwen Code автоматически добавит имя сервера в качестве префикса к названию инструмента 6\. В примере выше инструмент навигации puppeteer\_navigate от сервера web-browsing будет доступен модели под именем **web-browsing\_\_puppeteer\_navigate** 6\.  
* **Тонкая фильтрация через черные списки субагентов**:  
* Если вы хотите запретить субагенту доступ к конкретному инструменту MCP, используйте секцию disallowedTools с префиксом mcp\_\_ в формате: mcp\_\_\<имя\_сервера\>\_\_\<имя\_инструмента\> (как показано в примере с блокировкой скриншотов) 8, 11\.  
* Чтобы полностью заблокировать ВСЕ инструменты конкретного MCP-сервера для данного субагента, укажите в черном списке его алиас: \- "mcp\_\_web-browsing" 11\.  
* **Безопасность и окружение (Sandboxing)**:Если в Qwen Code включен режим песочницы (--sandbox), все вызываемые MCP-серверы будут запускаться **внутри изолированного контейнера** 12\. Это означает, что утилиты npx и node должны быть физически установлены внутри используемого Docker-образа песочницы, иначе запуск MCP-сервера завершится ошибкой 12\.
