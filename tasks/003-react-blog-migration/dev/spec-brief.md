# Бриф оркестратора для spec-writer

Задание: миграция блога md_articles с серверного рендера Jinja2 на React + TypeScript + Vite,
с полным редизайном. Все решения пользователя подтверждены — в «Открытые вопросы» их
не выносить, разве что обнаружатся новые развилки при исследовании.

## Подтверждённые решения

1. **Фронтенд**: новая папка `frontend/` в корне репо — Vite + React + TypeScript +
   React Router + Tailwind CSS v4. Прод-раздача сборки через FastAPI (StaticFiles +
   catch-all fallback на index.html для SPA-роутинга, кроме `/api/*`). Дев-режим:
   Vite dev server на `:5173` с прокси `/api` и `/static` на `:8000`.
2. **Дизайн**: современный красочный, свободная интерпретация. Bootstrap 5.3.8 полностью
   уходит. Зафиксируй в спеке краткое дизайн-направление (градиентные акценты, карточки
   со скруглением и тенями, плавные анимации, сочные акценты), чтобы frontend-dev не гадал.
3. **Темы сайта**: 4 темы сохраняются — `dark` / `light` / `midnight` / `aurora`, палитры
   адаптируются под новый дизайн. Переключение без перезагрузки: атрибут `data-theme`
   на `<html>` + CSS-переменные (сейчас висит на `data-bs-theme` Bootstrap — Bootstrap
   удаляется, механизм нужен собственный). Ключи localStorage сохранять: `theme`
   и `hljs-theme` (выбор вернувшихся посетителей не терять).
4. **Подсветка кода**: highlight.js, 15 тёмных тем (список в
   `templates/includes/_hljs_theme_select.html`), переключение без перезагрузки тем же
   приёмом swap активной `<link>`-таблицы стилей. Код всегда на тёмном фоне в любой
   теме сайта (как сейчас).
5. **Markdown**: серверный рендер остаётся — FastAPI рендерит MD в HTML тем же движком
   (расширения `fenced_code`, `tables`), React получает готовый HTML в JSON и вставляет
   его; подсветка — клиентский highlight.js поверх.
6. **Бэкенд**: новые JSON-эндпоинты для всего блога:
   - авторизация: register / login / logout / account + эндпоинт CSRF-токена + current_user;
   - статьи: список, фильтры, страница статьи с готовым HTML;
   - art_manage: управление реестром.
   Cookie-сессии starlette + bcrypt + CSRF остаются как есть (JWT не вводим).
   Флеш-сообщения сервера становятся клиентскими toast в React. Аватары — multipart
   upload через fetch. Ошибки `/api/*` — JSON. Предложи префикс API (например
   `/api/blog`) и зафиксируй контракт полей в таблице эндпоинтов.
7. **Удаление Jinja — последняя фаза**: `templates/*.html` (19 файлов), Jinja2Templates
   из `web_utils.py`, HTML-обработчики ошибок 403/404/500, старые роуты
   main/users/articles. НО: `templates/content_art/` (пользовательские .md-статьи)
   перенести в `fastapi-application/content_art/` и поправить путь в `schema_art.py`;
   реестр `md_articles/articles.yaml` и модели BlogUser/BlogPost не трогать.
8. **Не трогать**: демо-часть `/api/v1`, `/users` (example_sql), `/orders`
   (ex_order_product), `db_core`, alembic-миграции. Логика блога (валидация, тексты,
   поведение) переносится как есть — это порт, не реинжиниринг.
9. Ветка `react_fastapi` уже создана. Node v24.19.0 + npm 11.17.0 доступны.

## Что исследовать (точечно, не читать репозиторий целиком)

## Обязательные каркасы спеки

- Фазы backend-dev: 1–3 файла, бюджет ~10–15 ходов. Фазы frontend-dev режь по фичам,
  не по слоям: каркас + темы одним блоком, потом страницы. Frontend-файлов может быть
  больше трёх, но одна фаза = одна фича = одно делегирование; впиши это явно.
- У каждой фазы: исполнитель, файлы, контракт (имена/сигнатуры/форматы API),
  checkpoint-команда с ожиданием (backend: ruff + счётчик маршрутов + curl;
  frontend: `npm run build` успешна).
- Контракт backend-frontend зафиксируй ДО фазы 1 — таблица эндпоинтов: метод, путь,
  запрос, ответ, статусы.
- Чекпоинт `len(main_app.routes) == 42` умрёт: в переходный период старые роуты живут
  параллельно с новыми API, потом 16 объектов блога удаляются. Спека задаёт ожидаемый
  счётчик маршрутов на каждой фазе, меняющей маршруты, таблицей «фаза — ожидаемое
  число» (каждый GET/POST — отдельный объект; mount `/static` остаётся; SPA-fallback
  добавляется).
- Пункт-напоминание: после старта исполнения оркестратор обновит таблицу «Зоны
  и проверки» в AGENTS.md (frontend-dev получает зону `frontend/`) и
  `docs/11_md_articles.md` в конце.
- Критерии успеха — каждый проверяется командой (curl со статусом/телом, счётчик
  маршрутов, `npm run build`, ruff), включая: 4 темы и 15 тем подсветки без
  перезагрузки, рендер Markdown «так же», вход/регистрация/аккаунт/аватар, art_manage,
  SPA-роутинг (обновление страницы на `/art/...` не даёт 404), JSON-ошибки, регресс
  `/docs`, `/users/get_all_users`, `/orders/get_all_orders`, один из
  `/api/v1/dep_examples`.
- «Вне рамок» явно: `/api/v1`, example_sql, ex_order_product, db_core, alembic,
  тестовые фреймворки, SSR.
- Открытые вопросы — отдельным списком в конце.
