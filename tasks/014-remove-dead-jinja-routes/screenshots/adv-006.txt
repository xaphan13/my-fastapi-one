ADV-006: Регистрация — слабый пароль и валидация
================================================

Кейс W1: длина пароля = 1 ("1")
  POST { password="1", confirm_password="1" } -> 200 OK !!!
  Юзер создан с паролем "1".
  -> MEDIUM: нет проверки минимальной длины/сложности пароля.

Кейс W2: пароль отсутствует
  POST { без password } -> 422 password required — OK.

Кейс W3: password != confirm_password
  POST { password="A", confirm_password="B" } -> 422
    {"errors":{"confirm_password":["Fields must match."]}}  PASS.

Кейс W4 (наблюдение): длинный email 250 символов
  POST login { email="aaa...@x.x" } -> 401 (нет max_length в LoginIn.email).
  -> LOW: потенциальный DoS на хэширование через длинный пароль,
          если бэк не имеет ограничения длины в схеме RegisterIn.password.

Кейс W5 (наблюдение): email-валидатор
  Pydantic EmailStr не пускает "adv_X@test.local" (TLD .local длиной 5)?
  На самом деле .local валиден, но Pydantic использует email-validator,
  который проверяет deliverability. Возможно .local зарезан.
  Это не баг проекта, но может удивить.

Suggested severity: MEDIUM (слабый пароль), LOW (остальное)
